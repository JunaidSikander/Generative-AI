# How a Multimodal LLM Works

Each modality is encoded into vectors, projected into the model's shared embedding space, then consumed by the same transformer that handles text tokens.

---

## Processing Pipeline

`[Raw Inputs]` ➔ `[Modality Encoders]` ➔ `[Projection Layer]` ➔ `[Transformer]` ➔ `[Output]`

- **Raw Inputs:** Image / audio / text / document
- **Modality Encoders:** ViT for vision, audio encoder, tokenizer
- **Projection Layer:** Adapter maps features into LLM token space
- **Transformer:** Self-attention over the unified token stream
- **Output:** Text (and for some models, image/audio)

---

## Why This Matters in Practice

- **Images are expensive:** A single high-resolution image can cost hundreds to thousands of tokens, scaling with resolution and tiling.
- **Position is semantic:** The model attends to media in the order you place it, so interleave instructions and media deliberately.
- **Embeddings are model-specific:** Vision features from one model are not interchangeable with another's. You cannot mix encoders.

# An Embedding is a Learned Coordinate for Meaning

---

- **A Vector, Not a Label:** An encoder maps an input to a dense vector in $R^d$ — often 256 to 1024 numbers — instead of a sparse one-hot symbol.
- **Geometry Encodes Semantics:** Inputs with similar meaning land close together; cosine similarity (or dot product) measures how related two items are.
- **Learned, Not Hand-Built:** The coordinate system emerges from training on data, so the model captures nuance no manual feature set would.

---

> **A Single Embedding Space:** Represents semantic clustering where related item groups (e.g., _animals_, _vehicles_, _food_) gather into distinct spatial neighborhoods. _Nearby points mean similar things._

# Separately Trained Encoders Speak Different Languages

Train a text encoder and an image encoder independently and each builds its own coordinate system. The vector for the word "dog" and the vector for a photo of a dog are not comparable — they live in unrelated spaces.

---

## Isolated Vector Spaces

- **Text Encoder:** Maps textual inputs into _its own vector space_.
- **Image Encoder:** Maps visual inputs into _its own vector space_.

```
[ Text Encoder Space ]  ≠  [ Image Encoder Space ]
```

> **Core Issue:** No shared axes $\rightarrow$ cannot compare across modalities.

# Map every modality into one shared embedding space

Multimodal embedding models train the encoders together so that semantically matching inputs — a photo and its caption — land at nearly the same point. One space, many doors in.

---

## The Shared Space Architecture

![one shared embedding space](../../images/OneSharedEmbeddingSpace.png)

- **Inputs / Encoders:**
  - **Image:** Processed via a Vision encoder.
  - **Text:** Processed via a Text encoder.
  - **Audio:** Processed via an Audio encoder.
- **Shared Space:** All modalities project their encoded features into a single, unified vector space.
- **Semantic Alignment:** Matched items (e.g., an image and its corresponding text caption) sit closely together as clustered points within this shared space.

# Contrastive Learning Pulls True Pairs Together

**The CLIP Recipe:** Take a batch of $N$ image–text pairs. Embed all images and all texts, then build the $N \times N$ matrix of cosine similarities. A symmetric contrastive loss rewards the $N$ matching pairs on the diagonal and penalizes the $N^2 - N$ mismatches off it.

---

![Contrastive Learning Pulls True Pairs Together
](../../images/ContrastiveLearningPulls.png)

## Step-by-Step Alignment Process

1. **Encode:** Encode each image and each text in the batch.
2. **Normalize & Score:** L2-normalize, then score every image against every text.
3. **Optimize:** Maximize diagonal similarity; minimize the rest.
4. **Scale:** Temperature scales how sharp the contrast is.

---

> **Similarity Matrix ($N \times N$):** Matching pairs on the diagonal (e.g., dog–dog, car–car) are scored high as true matches, while off-diagonal mismatches ($N^2 - N$) are penalized.

# Two Encoders, One Projection, One Similarity Score

---

## Dual-Encoder Architecture Flow

- **Image Path:** `Image` ➔ `Vision Encoder (ViT / CNN)` ➔ `Project + L2-Normalize`
- **Text Path:** `Text` ➔ `Text Encoder (Transformer)` ➔ `Project + L2-Normalize`
- **Scoring:** Both normalized vectors output to **Cosine Similarity** ($\text{score} \in [-1, 1]$).

---

> **Why a Dual (Two-Tower) Encoder?** Each modality is embedded once, independently, so vectors can be precomputed and indexed. At query time, you only embed the query and run a fast nearest-neighbor search—making billion-scale cross-modal retrieval practical.

# The Content-Block Model

A message is a list of content blocks. Each block declares a `type` plus its data. Blocks of different modalities interleave in one ordered sequence; a provider adapter translates them into that API's native format.

---

## Anatomy of a Multimodal Message

- **Message Shell:** `HumanMessage(content=[...])`
- **Text Block:** `{"type": "text", "text": "..."}`
- **Image Block:** `{"type": "image", "source_type": "..."}`
- **File Block:** `{"type": "file", "mime_type": "pdf"}`

---

## Implementation Example (LangChain)

```python
# Build a multimodal HumanMessage
from langchain_core.messages import HumanMessage

msg = HumanMessage(
    content=[
        {"type": "text", "text": "Describe this image."},
        {
            "type": "image",
            "source_type": "url",
            "url": image_url,
        },
    ]
)

response = model.invoke([msg])
```


## 3. OpenAI-Style (Widely Accepted)

```python
# Chat Completions content format

```

## 4. Invoking the Model

```python

model = init_chat_model("gpt-5")

```

---

> **Tip:** URLs keep payloads small but the model host must be able to reach them; base64 is self-contained but inflates request size and token cost.

# Multimodal Prompt Templates

Wrap multimodal messages in a `ChatPromptTemplate` so the same instruction runs over many images, with variables for both text and media.

---

## Implementation Example

```python
from langchain_core.prompts import (
    ChatPromptTemplate, HumanMessagePromptTemplate
)

prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a vision QA expert."),
    ("user", [
        {
            "type": "text",
            "text": "{question}"
        },
        {
            "type": "image",
            "source_type": "base64",
            "mime_type": "image/png",
            "data": "{image_b64}"
        }
    ])
])

chain = prompt | model
chain.invoke({
    "question": "Any safety hazards?",
    "image_b64": site_photo_b64
})

```

---

## Key Capabilities

- **Variables everywhere:** Template both the question and the media so one chain serves many inputs.
- **Multiple images:** Add several image blocks and label them (e.g., "image 1 = before") in the text.
- **Swap models freely:** The same `prompt | model` chain runs on any multimodal provider.

# Multimodal Prompting Best Practices

---

## Core Guidelines

- **Anchor the instruction:** Put the task right next to the media it refers to; order is meaningful to the model.
- **Be explicit about the task:** "Extract", "compare", "locate", "transcribe" — name the operation, don't just show the image.
- **Demand a format:** Ask for JSON, a table, or a schema so output is parseable, not prose.
- **Label multiple inputs:** Number or name each image ("image 1 = before, image 2 = after") and reference them by label.
- **Allow uncertainty:** Tell the model to say "not visible" rather than hallucinate unreadable or absent details.
- **Mind cost & resolution:** Downscale images to the smallest size that preserves the detail your task needs.

# Prompting Patterns That Work

---

## 1. Describe & Ground (`Image`)

> _"Describe this photo. List every object you can see and where it is (top-left, center...). If text appears, transcribe it verbatim."_

---

## 2. Targeted Extraction (`Receipt`)

> _"From this receipt return JSON with keys: merchant, date (ISO-8601), line_items[{name, qty, price}], total. Use null for anything not visible."_

---

## 3. Compare Two Images (`Before / after`)

> _"Image 1 is BEFORE, image 2 is AFTER. List exactly what changed between them as bullet points. Ignore lighting differences."_

# Forcing Structured Output from Media

Pair a vision prompt with a schema so the model returns validated, typed data you can store directly.

---

## Implementation Example

```python
from pydantic import BaseModel, Field

class Invoice(BaseModel):
    merchant: str
    date: str = Field(desc="ISO-8601")
    total: float

# Bind the schema to the model
vision = model.with_structured_output(Invoice)

msg = HumanMessage(
    content=[
        {"type": "text", "text": "Extract the invoice."},
        {
            "type": "image",
            "source_type": "base64",
            "mime_type": "image/png",
            "data": invoice_b64,
        },
    ]
)

inv: Invoice = vision.invoke([msg])
```

---

## Common Application Patterns

- **Chart $\rightarrow$ Data:** _"Read this bar chart and return each category with its value as JSON. Note the units."_
- **OCR + Reasoning:** _"Transcribe the handwritten note, then tell me the single action item and its due date."_
- **UI $\rightarrow$ Structure:** _"This is an app screenshot. Output the visible UI as a JSON tree of components and labels."_

# Adding Multimodality to an AI System

_A production pipeline normalizes any input into content blocks, routes by modality, calls a multimodal model, and returns structured output downstream._

---

## Production Pipeline Stages

`[Ingest]` ➔ `[Normalize]` ➔ `[Route]` ➔ `[Reason]` ➔ `[Structure]`

- **Ingest:** Files, URLs, uploads, streams
- **Normalize:** Validate, resize, base64, $\rightarrow$ blocks
- **Route:** By modality; pre-process video
- **Reason:** Multimodal LLM + tools (refs only)
- **Structure:** Schema-validated JSON output

---

## Core Architecture Principles

- **Guardrails at the Edges:** Validate media type & size on ingest, strip EXIF/PII, and screen image-borne prompt injection before the model call. Validate the structured output on the way out.
- **Keep It Provider-Agnostic:** Build messages as standard content blocks and call through `init_chat_model`. Swapping GPT-5 $\leftrightarrow$ Claude $\leftrightarrow$ Gemini becomes a config change, not a rewrite.

# Multimodal RAG

> Because LangChain embeddings are text-only today, the common pattern is **describe-then-index**: caption each media item with a VLM, embed the caption, and at answer time hand the model both the retrieved text and the original media.

---

## Describe-Then-Index Pipeline Flow

1. **Media item:** Image / page / frame / chart
2. **Caption (VLM):** Generate a rich text description
3. **Embed + store:** Text embedding + media pointer
4. **Retrieve:** Query $\rightarrow$ nearest captions
5. **Generate:** LLM sees caption + original media

---

## Code Implementation Example

```python
# 1) Caption media with the VLM
caption = model.invoke([HumanMessage(content=[
    {"type": "text", "text": "Describe in detail."},
    {"type": "image", ...}])]).content

# 2) Index the caption text
vectorstore.add_texts([caption], metadatas=[{"media_id": id}])

```

---

## Alternative: True Multimodal Embeddings

- **Shared Space Search:** Use a CLIP-style model to embed images and text into one shared space for direct cross-modal search.
- **LangChain Integration:** Today that lives outside the core LangChain embedding interface — wire it in as a custom retriever.

# Production Considerations

Key engineering trade-offs and operational requirements when taking multimodal AI applications to production.

---

## Core Operational Pillars

- **Cost:** Image tokens scale with resolution and tiling — downscale, cache captions, and batch.
- **Latency:** Media inflates payloads and inference time; stream responses and pre-process async.
- **Context Limits:** A few high-res images can fill the window — send only what the task needs.
- **Security:** Screen for prompt injection hidden in images/PDFs; strip PII and EXIF on ingest.
- **Evaluation:** Build a labeled multimodal eval set; grade extraction accuracy, not just fluency.
- **Guardrails:** Validate output against a schema and reject low-confidence or out-of-policy results.

# Key Takeaways

---

## Core Multimodal Takeaways

- **Content blocks are the unit:** Every modality is a typed block; messages are ordered lists of them.
- **Chat models lead today:** They handle images, audio, video, and docs in; embeddings/stores are catching up.
- **Stay provider-agnostic:** Standard blocks + `init_chat_model` let you swap GPT-5, Claude, and Gemini freely.
- **Prompt for structure:** Anchor instructions to media and force schema-validated output.
- **RAG = describe-then-index:** Caption media to text until multimodal embeddings are first-class.
- **Engineer for production:** Budget tokens, screen inputs, and evaluate on real multimodal data.

---

> **Summary:** Multimodal development in LangChain centers on standard content blocks, leveraging chat models for native multimodal inputs, using describe-then-index for RAG, and maintaining provider-agnostic flexibility across leading LLM architectures.
